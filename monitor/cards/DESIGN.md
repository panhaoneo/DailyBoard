# 跟踪卡系统设计方案（monitor 模块升级）

> 目标：把 monitor 从"数据登记表"升级为**一手证据链跟踪系统**。
> 数据模型参考 `07_knowledge/公司跟踪卡/松发-跟踪卡-v1.md`（五问/证伪/指标字典/复盘三问），方法参考《利伏于众声未至》（逻辑穿透五问、证伪条件、两阶段）与《中远海能航线全景》（事件驱动、与价格互证）。
> 状态：待确认 → 确认后实现。

## 1. 现状与差距

| 需求 | 现状 |
|---|---|
| 标的跟踪卡（五问/门槛/证伪/状态三态） | 无。JSON 里只有指标表与 `sections` 叙述 |
| 事件流 | 有（`stocks/*.json` 的 `events`），但藏在 JSON 里、与叙述割裂 |
| 指标字典 | 半有（JSON 指标表，自动+手工混合，无"历史值"列） |
| 复盘三问历史 | 无 |
| 总览页状态灯/证伪警示 | 无（index 只有卡片+跟踪项数） |

## 2. 数据模型：双文件，职责分离

- `monitor/stocks/{code}.json` —— **保持不动**：自动抓取配置（行情/财报/预测/CTFI）+ 指标表。由 CI 每日刷新，人工改动走 `manual_value`/`status`（原有约定不变）。
- `monitor/cards/{code}.md` —— **新增，人工编辑的唯一日常入口**：跟踪卡（Markdown，git 管理，`build.py` 解析渲染）。

### 卡片文件格式（`cards/{code}.md`）

````markdown
---
status: 待验证            # 三态：逻辑强化中 | 待验证 | 已证伪
added: 2026-10-12         # 加入日期
reason: 一句话加入理由
gates: 增速,量价齐升,机构认可   # 筛选门槛，四选多：增速/量价齐升/股价新高/机构认可；未勾选不写
---

## 逻辑穿透五问
1. **需求为什么增长**（2026-10-12）：全球造船景气——存量替换 + 环保迭代 + 供需紧平衡。
2. **供给为什么跟不上**（2026-10-12）：船坞产能瓶颈，恒力 4 座坞趋饱和。
3. **谁有定价权**（2026-10-12）：新船价格指数 186.7（10-09），供应链自主度高。
4. **利润怎样传导**（2026-10-12）：船型升级 → 高附加值订单 → 毛利率提升。
5. **利润能不能变成现金**（2026-10-12）：`#待补` 经营现金流/净利润比。

## 证伪条件
- [ ] 新船价格指数连续回落（如连续 3 个月）
- [x] 月度订单断层（连续 2 个月无高价船型签约）   ← [x] = 已触发，总览页高亮

## 指标字典
| 指标 | 数据源 | 频率 | 最新值 | 历史值 |
|---|---|---|---|---|
| 新船价格指数 | 克拉克森（转述） | 周 | 186.7（10-09） | 185.1（09-25） |
| 逐笔订单明细 | imarine + 公司公告 | 事件 | +2 VLCC、+3 VLGC（10月） | 9 月 +8 VLCC |

## 事件流
- 2026-10-12 【签约】希腊船东追加 2 艘 VLCC，单价 1.32 亿美元
- 2026-09-16 【公告】恒力重工生效 1 艘 VLCC 订单
## 复盘三问
### 2026-10-12
1. 持仓理由是否成立：是（订单/价格指数均未走坏）
2. 逻辑是否被强化：是（新签订单持续超预期）
3. 处于逻辑兑现还是业绩兑现：逻辑兑现（第一阶段，业绩仅兑现 H1）
## 交易纪律
- 止损：技术位 173 附近（-6.5%），跌破执行
- 仓位：100 股 × 成本 185 = 18,500 元（约占总资金 31%）
````

解析规则（`cards.py`，纯标准库，无新依赖）：

- front matter：`---` 包裹的 `key: value` 行；`gates` 按逗号/顿号拆分，值必须是四门槛之一。
- 五问：`1. **标题**（YYYY-MM-DD）：正文`，正文可多行，遇到下一个 `N.` 或 `##` 结束。标题匹配五个关键词（需求/供给/定价/传导/现金），日期为更新时间戳。
- 证伪条件：`- [ ]`（未触发）/ `- [x]`（已触发）列表。
- 指标字典：5 列表格（指标/数据源/频率/最新值/历史值），手工增删行。
- 事件流：`- YYYY-MM-DD 【类型】内容`，类型取 签约/交付/公告/指标更新/判断变更/其他；新事件**加在列表最上方**。页面按日期倒序渲染。
- 复盘三问：每个 `### YYYY-MM-DD` 一节，节内三条编号问答；多次出现即历史，页面最新在上。
- 交易纪律：普通列表。
- 未知区块忽略并在构建日志告警；卡片缺失或解析失败时页面回退原样 + 显示"跟踪卡待建"提示。

### 事件流归属（重要变更）

- 有卡片（`cards/{code}.md` 存在）的股票：**事件流以卡片为准**，JSON 的 `events` 不再渲染（避免两处维护）。
- 迁移：实现时把 `603268.json` 现有 7 条 `events` 迁入卡片，随后 JSON 中删除 `events` 键。
- 无卡片的股票：继续渲染 JSON `events`，行为不变。

## 3. 页面结构

### 个股页 `docs/{code}.html`（在现有页面基础上插入）

```
┌ 头部：名称/代码/行情/一句话摘要（不变，加一行状态灯）
├ 跟踪卡（新）：加入理由 + 加入日期 + 四门槛徽章
├ 逻辑穿透五问（新）：5 条问答，各带更新时间戳
├ 证伪条件（新）：勾选列表；已触发项红色高亮
├ 指标字典（新）：5 列表格
├ 指标与事件跟踪（原有：自动+手工指标表，不变）
├ 财报明细（原有）
├ 事件流（新位置：以卡片为准，时间线样式沿用现有 .events）
├ 复盘三问（新）：历史列表，最新在上
├ 交易纪律（新）
└ sections 叙述块（原有）
```

### 总览页 `docs/index.html`（升级现有卡片）

每只股票卡片增加：

- **状态灯**：● 绿=逻辑强化中 / ● 黄=待验证 / ● 红=已证伪（无卡片时灰=未建卡）。
- **最近事件**：卡片事件流最新 1 条（日期+文本）。
- **证伪警示**：有 `[x]` 已触发项时，卡片红色描边 + "⚠ 证伪条件已触发 N 条"。
- 主题卡片（猪周期）不变。

## 4. 每日 5 分钟维护流程

| 操作 | 步骤 | 耗时 |
|---|---|---|
| 追加事件 | 打开 `cards/{code}.md`，在「## 事件流」标题下一行加 `- 日期 【类型】内容` → push | ≤1 分钟 |
| 更新指标 | 「## 指标字典」改最新值并把旧值挪进历史值列（或 JSON 的 manual_value）→ push | 1–2 分钟 |
| 新增标的 | 复制 `cards/_模板.md` 为 `cards/{code}.md` 填卡 + 在 `stocks/{code}.json` 建指标配置 → push | ~10 分钟（一次性） |
| 复盘 | 在「## 复盘三问」顶部加 `### 日期` + 三条问答 → push | 1–2 分钟 |

发布链路（沿用现有部署，零改动）：本地 `cd monitor && python3 build.py` 预览 → push main → GitHub Actions 部署 Pages（deploy 步骤会重新执行 build.py，卡片自动生效）；即便不 push，CI 每日 10:00（北京时间）也会重建。

## 6. 验收对照

- 松发完整卡（五问+证伪+指标+事件）≤10 分钟：按模板填即可，样例卡即模板实测。
- 每日追加事件 ≤1 分钟：一行 Markdown + push。
- 本地可预览、随现有站点发布：`python3 build.py` / GitHub Pages 链路不变。
- 纯文本、无后端、无新依赖、无自动抓取新增：全部满足。
