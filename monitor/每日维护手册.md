# 每日 5 分钟维护手册（monitor 跟踪卡）

> 跟踪卡系统：每只股票一张 `monitor/cards/{代码}.md`，Markdown 手写、git 管理，页面由 CI 自动重建。
> 格式规范与页面结构见 `monitor/cards/DESIGN.md`；模板见 `monitor/cards/_模板.md`。
> 线上入口：https://panhaoneo.github.io/DailyBoard/monitor/

## 三类日常操作（全部 ≤5 分钟）

### 1. 追加事件（最常用，≤1 分钟）

打开 `monitor/cards/{代码}.md`，在 `## 事件流` 标题的下一行加一行：

```markdown
## 事件流
- 2026-10-12 【签约】希腊船东追加 2 艘 VLCC，单价 1.32 亿美元
```

- 日期写事件发生日；类型用：签约 / 交付 / 公告 / 指标更新 / 判断变更
- 新事件永远加在**最上方**（页面自动按日期倒序）
- 加完 `git add monitor && git commit && git push` 即可，CI 自动发布

### 2. 更新指标（1–2 分钟）

- **卡片指标字典**（手填类，如新船价格指数）：在 `## 指标字典` 表格里改「最新值」，把旧值挪进「历史值」列。
- **自动指标**（行情/财报/机构预测）：不用管，CI 每天抓。
- **JSON 手工指标**（`stocks/{代码}.json` 的 `manual_value`/`status`）：按原约定改，别动自动字段。

### 3. 新增标的（一次性 ~10 分钟）

1. `cp monitor/cards/_模板.md monitor/cards/{代码}.md`，填 front matter + 五问 + 证伪 + 指标字典。
2. `monitor/stocks/{代码}.json` 按现有格式建指标配置（`market` 填 `1.{代码}` 沪 / `0.{代码}` 深）。
3. 本地 `cd monitor && python3 build.py` 看效果，push。

## 复盘（每周一次，1–2 分钟）

在 `## 复盘三问` 顶部加一节（历史自动保留，页面最新在上）：

```markdown
## 复盘三问
### 2026-10-19
1. 持仓理由是否成立：…
2. 逻辑是否被强化：…
3. 处于逻辑兑现还是业绩兑现：…
```

## 状态与证伪

- front matter `status:` 三选一：`逻辑强化中` / `待验证` / `已证伪` → 总览页状态灯 绿/黄/红。
- 证伪条件把 `- [ ]` 改成 `- [x]` 即"已触发" → 总览页该股票卡片变红并显示警示，此时按纪律重新评估。

## 本地预览与发布

```bash
cd monitor && python3 build.py        # 生成 docs/*.html（本地东财偶发失败不影响生成）
open docs/index.html                  # 或 open docs/603268.html
```

发布（沿用现有部署，零新增配置）：

- **push main** → GitHub Actions 自动构建并部署 Pages（几分钟内上线）。
- 不 push 也会在 CI 每日定时任务运行时自动重建（实际执行时间比 cron 晚数小时，属正常现象）。
- 提交前注意：本地跑 build.py 若东财行情失败会生成降级页面，先看 diff 再提交（老规矩）。

## 常见问题

- **页面没变化？** 检查日期格式 `YYYY-MM-DD`、区块标题是否含关键词（五问/证伪/指标字典/事件流/复盘三问/交易纪律）；构建日志会打印卡片告警。
- **front matter 改动没生效？** `---` 必须成对、顶格；`gates` 只认四个词：增速/量价齐升/股价新高/机构认可。
- **要改自动抓取？** 走原流程：`build.py` 加抓取函数 → `render_indicator_cell` 加分支 → JSON 加 `auto_ref` →（有状态时）改 `monitor-update.yml` 的 git add 列表。
